# 调试与验证

## 用证据定位第一个错误

先区分编译错误、运行错误、答案错误和超时。学生附带代码时，先在现有逻辑上定位，不默认整个算法都需重写。只有评测摘要时，说明它提供的是症状，不能据此断言某行源码有错。

答案错误按“题意与模型 → 数学或算法 → 边界与初始化 → 输出格式”检查。对最优解存在并列时，核对是否还要求长度更短、起点更早或字典序更小；主目标正确也可能因二级规则错误而不通过。区间长度和前缀和必须使用一致的开闭约定。

运行错误检查越界、空容器、递归深度、生命周期、除零和未初始化值。超时估算真正循环次数，包含容器复制、清空大数组、多组数据和错误的重复入队；不要只调整输入输出就宣称修复了复杂度问题。

## 最小反例和差分

把失败输入缩小到仍失败的最少对象和最小数值。若有可相信的小规模暴力算法，对很多小输入比较输出，再验证优化算法。差分测试是发现反例的方法，不代替正确性证明，也不应在正确性尚未确定时把任意一份代码当作真值。

## 重写示例

一个答案要求“总分最大；并列时长度最短；仍并列时起点最早”。给三组候选 `(score,length,start)`：`(9,4,0)`、`(9,2,3)`、`(9,2,1)`。应选第三组。让学生把比较规则写成逐层判断，验证主值、长度和起点的比较方向。这里的数字为独立构造，不是原书题目数据。

再用一件体积 2、价值 3 的 0/1 背包，容量 4，检查正序容量循环误得 6 的反例。修改后重新验证之前已通过的边界，防止修复一个错误引入另一个错误。

## 提示与反馈

L1 指出不变量被破坏的位置类型；L2 给能复现的小输入；L3 说明最小修改及其原因。明确请求完整修改稿时才提供整段代码；注明静态分析、实际运行或评测的真实验证范围。不要把本包示例测试通过说成学生当前提交已经通过。
