# 建模与复杂度

## 核心方法

先把故事转成对象、允许的操作、目标和约束。要求学生用一句话描述“一个解是什么”，再说明如何验证一个候选解。若题意缺少决定算法的条件，指出具体缺失项；暂用参数化分析，不默认为熟悉的模板题。

按“最直接的枚举 → 造成重复的维度 → 能复用的信息”改进。枚举次数由数据规模决定：一个几何题坐标上界很大、障碍物很少时，值得研究边界是否能由障碍物坐标确定；这必须证明，不能直接对所有坐标逐格穷举，也不能在未证明时直接做坐标压缩。

多阶段问题中，如果未来选择依赖“当前地点和时间”，只用地点作状态会丢失约束。考虑状态 `(时刻, 地点)`，按时间方向连接允许的转移；容量、费用和可达性分别表示不同限制，不把“最小最大费用”直接改成“总费用最小”。

## 教学步骤

1. 给出输入量的含义及数量级，询问结果是存在性、最优值、方案还是方案数。
2. 手算两个候选方案，验证边界和目标；用朴素程序理解答案空间。
3. 估算候选状态数乘以每次转移成本，含排序、建图、初始化与多组数据。
4. 选择优化时说明减少了什么重复；证明压缩后的状态仍区分所有影响未来的条件。

## 重写示例

包裹只能在每天结束时从一个仓库移动到另一个仓库，最多三天。两个方案都在仓库 A，但分别在第 0 天和第 2 天，后续可用运输机会不同。让学生解释为何 `visited[A]` 不足，改为 `visited[day][A]`。若还要求满足容量，就进一步讨论流量而不是把每个包裹独立视作一条最短路。

## 分级提示与检查

L1：“到达同一个地点时，剩余时间相同吗？”L2：“在状态中加入影响未来的量。”L3：列出状态、转移和终止条件。L4 只有明确请求后才给完整实现。

检查学生能否给出状态充分性的理由。反例：把时间删去后，两条不同时间的路径被错误合并。复杂度要用实际状态数量计算，而非只看题中地点数。
